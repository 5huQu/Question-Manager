# T1：调度分级与旧快照展示

## 目标

把“持续文字输入”和“明确的视图/结构操作”分成不同调度策略，避免所有变化统一经过 700ms 稳定延迟和 300ms 分页防抖。

## 调度分类

- `typing`：持续输入，允许尾随防抖和低优先级布局。
- `structure`：插入、删除、移动块或分页符，立即更新交互层，尽快开始局部布局。
- `view`：切换连续流、页面编辑、打印预览，优先使用最近快照，不等待新测量才切换界面。
- `variant`：切换学生版/教师版，优先查询对应缓存。
- `export`：必须等待当前 revision 的精确 settled 快照，不允许使用 stale 结果。

## 工作范围

- 为布局请求增加明确的 reason/priority，而不是从对象引用变化推断用户意图。
- 将现有 700ms 和 300ms 延时只用于 `typing`。
- 视图切换立即完成控件和容器状态更新。
- 新布局计算期间保留上一对一致的 `{document, pagination}` 展示快照。
- 在不打断编辑的区域显示低干扰“正在重新排版”状态。
- 用户继续输入或再次切换时取消旧 generation。

## 正确性边界

- stale 快照只能用于编辑器展示，不能解锁导出。
- 不得把新文档与旧 pagination 混合渲染；快照必须成对切换。
- 选区、滚动位置和当前页在快照替换时保持稳定。
- 首次进入从未计算过的视图允许展示骨架，但不能冻结整个页面。

## 验收

- 重复视图切换不再稳定出现人为的 300ms/700ms 等待。
- 连续输入仍不会逐键触发全量分页。
- 快速切换视图或版本时没有旧 generation 覆盖新结果。
- 导出 readiness 的现有安全门槛保持不变。

## 实施结果（2026-08-05）

- 新增 `LayoutRequest`，显式携带 `typing/structure/view/variant/export` reason 与 `background/interactive/blocking` priority。
- 只有 `typing` 保留 700ms 稳定快照和 300ms 分页防抖；结构、视图与版本请求直接进入下一次可中断布局。
- 视图和打印版本切换前先冲刷编辑器尚未同步的文字，避免预览读取 350ms 模型合并窗口之前的旧内容。
- A4 重排期间继续展示上一份一致的文档、分页与 choice layout 快照；父层仍收到 `pagination: null` 的 preparing 状态，因此导出不会使用 stale 快照。
- 页面编辑和打印预览增加低干扰的“正在准备/重新排版”状态；非激活预览不发布可见状态。
- 已覆盖 typing 防抖、结构/视图/版本即时请求、快速 view 请求取消旧 typing 定时器、A4 成对旧快照和旧 generation 丢弃。
