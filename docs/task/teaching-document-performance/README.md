# 文档编辑器性能优化任务集

## 目标

降低长文档编辑时以下操作的感知延迟和主线程占用：

- 连续流、页面编辑、打印预览三种视图之间切换。
- 学生版、教师版之间切换。
- 插入、删除或移动分页符及其他结构块。
- 内容变化后的精确分页与页面重绘。

优化必须保持编辑、预览和 PDF 导出使用同一套排版语义，不得通过降低导出精度、复制另一套分页算法或跳过资源就绪校验来换取速度。

## 当前判断

当前实现已有 generation 中断、输入防抖、旧分页结果保留、离屏绘制和统一测量编排等优化。主要瓶颈已从普通 React 重渲染转为：

1. 分页缓存以整篇文档为粒度，局部变化会使完整隐藏测量树失效。
2. 页面编辑与打印预览各自维护分页生命周期，无法稳定共享测量与分页快照。
3. 页面编辑存在 700ms 稳定快照延迟和 300ms 分页防抖；这些策略没有区分文字输入与明确的视图/结构操作。
4. 学生版/教师版通过整篇文档转换表达，资源签名又包含完整内容 JSON，导致不必要的资源等待和全量失效。
5. 段落行测量按字素调用 DOM Range 几何读取，长文本的主线程成本接近按字符增长。
6. 外部结构命令可能触发完整 ProseMirror JSON 转换、比较和 `setContent()`。

## 目标架构

```text
文档模型 + 变更范围
        │
        ▼
Layout Coordinator
 ├─ Resource State Cache
 ├─ Block Measurement Cache
 ├─ Pagination Snapshot Cache
 └─ Generation / Abort / Scheduling
        │
        ├─ 连续流
        ├─ 页面编辑
        └─ 打印预览 / 导出
```

核心原则：

- 分页仍是派生状态，不写回持久化文档。
- 编辑器可以短暂展示上一份一致的分页快照；导出只能使用当前 revision 的 settled 快照。
- 资源就绪、块测量和页分配使用不同签名，不再用一个整篇 JSON 签名表达所有失效原因。
- 缓存以稳定 block id 和明确布局输入为基础，禁止依赖组件挂载顺序或偶然对象引用。
- 用户操作先获得即时反馈，精确分页在可中断的后台阶段完成。

## 推荐实施顺序

必须按以下顺序推进；后续任务可以在满足依赖后并行验证，但不建议跳过前置契约：

| 顺序 | 任务 | 原因 |
| --- | --- | --- |
| 1 | T0 基线、埋点与性能预算 | 没有分阶段耗时就无法判断优化是否真实有效。 |
| 2 | T1 调度分级与旧快照展示 | 风险较低，可先消除人为等待和切换白屏。 |
| 3 | T2 段落测量热路径优化 | 当前最明显的算法级主线程热点，可独立验证正确性。 |
| 4 | T3 签名拆分与版本缓存 | 为共享协调器建立可靠的缓存键和失效语义。 |
| 5 | T4 统一 Layout Coordinator | 合并两套分页生命周期，形成单一派生状态来源。 |
| 6 | T5 按块增量测量与局部分页 | 在统一协调器上实现最大规模收益，避免过早堆叠局部缓存。 |
| 7 | T6 ProseMirror 结构命令快速路径 | 利用变更范围协议优化分页符等操作，同时保证撤销和选区。 |
| 8 | T7 页面窗口化与集成验收 | 在计算管线稳定后减少多页 React/DOM 展示成本并完成总回归。 |

依赖关系：

```text
T0 → T1 → T2 → T3 → T4 → T5 → T6 → T7
                 └──────────────→ T7
```

## 统一验收原则

- 所有性能对比必须使用同一机器、同一构建模式、同一 fixture，并报告中位数与 p95。
- 不只统计总耗时；至少拆分隐藏树提交、资源等待、DOM 测量、纯分页和可见页面提交。
- 性能优化不得改变页数、分页片段、诊断、题号、页眉页脚、答案显示或 PDF 结果。
- 用户连续输入或快速切换时，旧 generation 必须可取消，不能反复提交过期布局。
- 必须覆盖普通段落、长题目、选项、图片、知识卡片、表格、公式、分页符和缺失资源。
- 不改变现有 API 路径、数据库结构或服务端响应形状；如任务实施中确有必要，必须先单独更新本任务集契约并获得确认。

## 非目标

- 首轮不优先引入 Web Worker。DOM 渲染和几何测量仍只能在主线程，纯分页算法不是当前首要热点。
- 不用降低分页精度、关闭段落拆分或延迟题目资源加载掩盖问题。
- 不重写整个文档编辑器，不同时进行视觉大改版。
- 不把自动分页结果持久化到文档 JSON。
