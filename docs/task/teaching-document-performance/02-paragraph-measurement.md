# T2：段落测量热路径优化

## 目标

降低长段落和长题目中的 DOM Range 调用次数，同时保持精确的行边界和跨页片段语义。

## 当前热点

当前段落测量会遍历每个字素，并为每个字素创建 Range、读取 `getClientRects()`。这会产生大量同步布局读取，成本随字符数快速增长。

## 推荐算法

1. 对一个 inline 或连续文本段建立完整 Range，一次取得行盒集合。
2. 按行盒 top/bottom 合并为逻辑行。
3. 只在每行末端附近二分搜索文本 offset，确定精确 start/end cursor。
4. 原子 inline、硬换行、公式和未知节点继续保留明确边界。
5. 将 DOM 读取集中到测量阶段，避免读写交错造成额外强制布局。

目标复杂度从接近 `O(字符数 × DOM 几何读取)` 降为 `O(行数 × log 字符数)`。

## 必须覆盖

- 中文、英文、数字和混合字体。
- emoji、组合字符、代理对和扩展字素。
- 粗体、斜体、下划线、行内公式和硬换行。
- 同一段内跨多个 Text node。
- 卡片段落、题干、答案和解析区域。
- 空段落、超长不可断字符串和浏览器返回多 rect 的情况。

## 降级策略

如果批量 Range 无法稳定确定边界，仅对异常行回退到逐字素测量；不得让整篇文档全部回退。

## 验收

- 现有 paragraph/question/box 分页测试全部通过。
- 新增新旧算法对照测试，页面数、片段 cursor 和诊断一致。
- M/L fixture 的 Range 调用数和测量耗时显著下降。
- 不引入新的零高、重复行或字符丢失问题。

## 实施结果

状态：`completed`（2026-08-05）

实现采用兼容式适配器扩展：原有 `measureText()` 继续作为边界探针和降级路径，新增可选的 `measureTextRange()` 收集完整 inline 的全部 rect。浏览器适配器启用批量路径；未实现新方法的测试或外部适配器仍保持原有逐字素语义。

批量路径按以下顺序工作：

1. 一次完整 Range 读取 inline 的全部 rect，并按 top/垂直重叠归并逻辑行。
2. 在字素边界数组上二分查找各行切换位置，只测量候选字素。
3. 单个候选 Range 异常时，仅对当前行边界线性探测；整段行盒不可用时才降级该 inline，不影响文档中的其他段落。
4. 文本、原子 inline、行内公式和硬换行继续通过同一 `InlineCursor` 半开区间契约合并。

新增覆盖包括：64 字/4 行调用量、emoji ZWJ 序列、组合字符、多 rect 同行归并和异常边界局部回退。64 字合成用例由旧路径的 64 次文本 Range 读取降为 1 次整段读取和少于 24 次边界探针。

显式性能追踪新增以下 metadata，仅在 `layoutPerf` 开启时计数：

- `paragraphTextRangeCalls`：完整文本 Range 次数。
- `paragraphTextProbeCalls`：二分或局部回退的字素探针次数。
- `paragraphAtomicRectCalls`：原子 inline 的元素 rect 次数，不计入文本 Range 总数。
